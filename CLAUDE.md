# Stat Pop Board: agent guide

Read this file and `docs/HANDOFF.md` before changing anything. `docs/CONTEXT.md` has the full history: every decision with its reasoning, the research, and what's still unverified. Read it before reopening any decision.

## What this is

A personal second-monitor tool for William, who runs the graphics computer for Montana PBS broadcasts of Montana State (MSU) volleyball, basketball and football. During a match he watches the public StatBroadcast stats page and types short stat "pops" into the graphics system by hand. This site surfaces the few stats worth popping right now, pre-formatted the way he types them.

- **Live:** https://stat-pop-board.vercel.app (`/` board, `/setup` reader setup, `/practice` stand-in stats page, `/replay` demo)
- **Personal and non-commercial.** It is not connected to the graphics software, and the network never sees the data. It runs on one computer, with the stats tab and the board window side by side.
- **Sport support:** volleyball only, for now. The reader recognizes a basketball page and says it isn't supported yet.

## Hard rules

1. **Never fetch StatBroadcast from a server or a script.** That means no proxy, scraper, poller, headless browser, serverless route, cron job or "API" that requests `statbroadcast.com`, and nothing that works around its bot protection. StatBroadcast's terms grant access "only for personal, non-commercial use through the standard StatBroadcast web interface". The design keeps to that: the reader runs inside the tab William already has open and reads only what that page shows. If a feature seems to need server-side access, stop and ask William instead.
2. **The reader makes no network requests of its own.** The only exception is the stylesheet and fonts for its in-tab overlay. Data leaves the stats tab only through `window.postMessage` to the board window on the same computer, with exact origin checks on both sides.
3. **No backend, accounts or database.** Per-user state lives in `localStorage` on the board's origin.
4. **`spb.js` stays a single self-contained IIFE.** It is injected into a third-party page by a bookmarklet, a console paste or Tampermonkey. No imports, no external dependencies, and no globals besides `window.SPB`. It must survive being loaded twice: it has a guard, and a second load just calls `SPB.show()`.
5. **Never edit `site/` by hand.** Edit `src/`, `data/`, or the page templates in `tools/build_site.py`, then run `python3 tools/build_site.py` and commit `site/` and `vercel.json` together with the source change.
6. **Match nights.** Don't push to `main` within about 2 hours of a broadcast unless William asks. Prefer a branch, with its Vercel preview tested on `/practice`.

## How it works

```
 stats tab (statbroadcast.com, William's own browser tab)        board window (stat-pop-board.vercel.app)
 ┌───────────────────────────────────────────┐   postMessage    ┌──────────────────────────────────────────┐
 │ spb.js reader                              │ ───────────────▶ │ index.html + assets/live.js               │
 │  - parses tab title: "UI 18, MSU 24 - SET 3"│  {type:'state'} │  - PopEngine.update(snapshot, new lines)  │
 │  - header-mapped box-score tables           │ ◀─────────────── │  - BoardView renders the 2x2 board        │
 │  - new play-by-play lines (MutationObserver)│  {type:'ack'}    │  - impact-player picker, Reader check     │
 │  - small dock bar; "Show here" overlay      │  {type:'hello'}  │  - localStorage: stars, hidden, recent    │
 └───────────────────────────────────────────┘                  └──────────────────────────────────────────┘
```

**Starting the reader.** There are four ways, all built by `/setup` from `location.origin`:

- bookmarklet (recommended on the work computer)
- DevTools console paste of the full `spb.js`, prefixed with `window.__spbOrigin=...`, which gets around a page CSP that blocks the script load
- Tampermonkey: one-click install from `/stat-pop-board.user.js`, generated by the build. The reader comes in through `@require`, so a page CSP can't block it, and `@updateURL` keeps it current.
- `/practice`, which loads `spb.js` by itself unless `?manual=1`

`SPB.origin`, the board address the reader talks to, comes from `window.__spbOrigin` (set by the bookmarklet and the console code), then the script's own URL, then `PROD_ORIGIN` in `tools/build_site.py`. That last fallback is what the Tampermonkey `@require` case uses. If the site ever moves to a custom domain, update `PROD_ORIGIN`. The board warns when the stats tab reports an older reader `VERSION` than its own.

**Linking.** It works in both directions:

- The board's "Open stats page" opens the stats tab with `window.open(href, 'spb-stats')`, and the reader posts `reader-hello` to `window.opener`.
- The reader dock's "Open board" opens `ORIGIN + '/?from=stats'` as window `stat-pop-board`.

The board pings `hello` every 3 s whenever it hasn't had state for 6 s. That pinging is what relinks after a stats-tab reload.

**Message protocol.** Every message carries `spb: 1`.

- Reader to board: `{type:'state', v, inst, eventId, seq, sentAt, ok, kind, error, snap, lines: last 12 {id,text,at}, diag, colors}`. It is sent on change, or at least every 2 s. `colors` is `{teamKey: '#rrggbb'}` for the two teams, when set.
- Board to reader: `{type:'ack', seq, colors}` for every state, plus `{type:'hello'}`. Each side adopts a `colors` entry it doesn't have yet, so a colour picked in either tab reaches the other.
- The reader accepts messages only from `SPB.origin`. The board accepts its own origin or `https://*.statbroadcast.com`.
- `eventId` is the URL `id` param, `practice`, or `page`. A change in `eventId` resets the engine. A new `inst` (the reader was reloaded) marks only its newest line as live.

**Snapshot contract.** This is what any reader must produce. The engine is pure logic and runs in Node.

```
{ sport:'vb', status:'pre'|'live'|'final', set, score:{home,away}, setsWon:{home,away},
  teams:{ home:{code,name,players:[P],totals?}, away:{...} } }
P = { uni, first, last, k, e, ta, a, sa, se, re, dig, bs, ba, be }
```

**Engine (`src/engine.js`).**

- **Notability.** Each stat is scored against a par that scales with effective sets played (`vbEffSets`). So 5 kills is notable in set 1 and ordinary by set 4. A sub-par stat like "1 block" can still appear, but only greyed, as filler (see Board makeup).
- **Pops.** Each pop is the button label William uses: Attacks, Kills, Blocks, Digs, Assists, Aces, Points, plus the combos Attacks & Blocks, Attacks & Digs, Digs & Blocks and Assists & Digs. A player card shows up to 3 pops and at least 2 when the player has 2 different stats. Options below pop level (score < 0.8) are flagged `dim` and shown greyed.
- **Impact score.** Impact = best pop + 0.35 × second pop + recent play involvement. Boosts: pinned (the last play named the player) +100, serving streak of 3 or more +1.2, starred +0.35, already on the board +0.3.
- **Board makeup (v0.3.0).** Each side always fills 3 player cards (as long as 3 players have a stat) and 2 team cards (1 in the first few rallies). Order: Pin-held cards, then notable or live cards by impact, then the most active remaining players as greyed filler (`dim`). A card that just arrived gets a +1.5 stickiness bonus for 4 rallies, so cards don't flicker. Cards keep their slots between updates.
- **Pin (William's button, v0.3.0).** Keeps a player's card on the board, still updating, for 10 minutes or until he clicks Unpin. Engine API: `toggleHold(key)`, `expireHolds()`; state is `user.held`, separate from `mem.pins` (the last-play pin). Max 3 per side; a 4th releases that side's oldest. Pass and Hide release the pin. The board checks for expiry every second.
- **Impact stars.** A starred player always gets a card on their side.
- **Team colours (v0.3.3).** The swatch beside a team name opens the browser colour picker. The colour is stored per team (`spb:color:<teamKey>`), not per side, so it survives Swap sides and comes back the next time that team plays. Jersey ink flips to white on a dark colour.
- **Pass and Hide.** Pass skips a player for 10 rallies. Hide removes them until they're unhidden.
- **Team cards.** Notable: scoring runs, set hit %, team hit %, kills, blocks, aces, digs, service errors, and a set summary. Filler (greyed, always ranked below notable): team hit %, kills, blocks, digs, aces and set hit %, whenever the team has that stat.
- **Alerts.** Set point, match point, timeout, challenge, penalty, sub, set won and final.
- **Rotation.** A tracker built from the serve order.

**Reader (`src/reader.js`).**

- **Paused.** StatBroadcast prefixes the tab title with `[Paused]` when it stops refreshing the page (seen 2026-10-17). The reader strips any leading `[tag]` before parsing (otherwise it lands in the visitor's team code and rekeys stars and colours) and reports `diag.paused`; the board shows mode **Paused** with a notice, and the dock and overlay say so. The reader never pokes the page to resume it.
- **Tables.** The table's headers are mapped (K, E, TA, PCT, A, SA, SE, RE, DIG, BS, BA, BE…), and a table counts as volleyball only if it has K plus TA or PCT plus at least 2 more columns.
- **Sides.** Which team a table belongs to comes from nearby captions and headings.
- **Play lines.** A batch of 3 or fewer changed lines counts as new plays, repeats included. A bigger batch means the page redrew, so only lines never seen before count. The same text within 3 s is dropped as a duplicate.

## Gotchas

- **`[hidden] { display: none !important; }`** in `site.css` is load-bearing, because `.start` and `.check` set `display: grid`.
- **`normName` in `engine.js`** strips accents with a character class written as literal combining characters (U+0300 to U+036F). Some editors show it as blank. It is equivalent to `/[̀-ͯ]/g`, and switching back to the escaped form is fine.
- **The board reuses the `spb-stats` tab** for every new link, including the practice page. That's intended.
- **COOP or CSP risk.** If StatBroadcast sends a COOP header, the window link between tabs can break. The fallback is the dock's "Show here" in-tab board. If the page's CSP blocks the bookmarklet's script load, the fallback is the console paste.
- **Cache-busting.** Bump `VERSION` in `tools/build_site.py` for any change William should see. It updates every `?v=` URL and shows in Reader check, which is how you confirm he has the new reader.
- **Copy rules.** UI copy is short, plain and operator-facing. Labels must match how William names pops in the graphics software.
